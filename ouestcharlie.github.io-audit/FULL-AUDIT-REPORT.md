## Baseline executive summary (2026-10-11, before corrections)

**SEO Health Score: 64 / 100**

| Category | Weight | Score |
|---|---|---|
| Technical SEO | 22% | 80 |
| Content Quality | 23% | 68 |

The site's fundamentals are sound: HTTPS with HSTS, a valid sitemap, permissive robots.txt, self-referencing canonicals, Search Console verification, an RSS feed, and long-form first-hand tutorials (800–1,600 words). Most losses come from metadata generated by default by `jekyll-seo-tag`: descriptions that are whole first paragraphs, titles that overflow the SERP, a copyright string used as the author entity, and a video used as a social image. The homepage is also thin and has no H1. Most of these take one line of front matter or `_config.yml` to fix.

### Top 5 issues
1. **Install post's `og:image` is a 9 MB MP4.** No social network or Google Discover can use it, so the most important page gets no preview card.
2. **Author entity is `"(c) Antoine Hue"`** in every BlogPosting's `author` and `publisher`, and in `<meta name="author">`. That breaks E-E-A-T attribution and makes the publisher look like a person named "(c)".
3. **Every meta description is too long (239–534 chars).** No post has a `description:`, so the first paragraph is used and Google rewrites or truncates it.
4. **The homepage has no H1, 173 words, no og:image, and a 113-character title.** It is the site's main entry point and says little about what Woof is.
5. **Mobile LCP is slow in lab tests: 5.2 s on the homepage and 10.4 s on the Claude how-to.** The cause is a 669 KB 850×850 logo shown at 32 px on every page (also used as favicon), plus unoptimised PNG screenshots of up to 936 KB.

### Top 5 quick wins
1. In the install post, change `image:` to `/assets/OuEstCharlieWoof_2026-09-01.jpg` (the video poster).
2. ~~In `_config.yml`, make `author:` a name + URL and print `© {{ site.author.name }}` in the footer.~~ Done.
3. Add a `description:` of 120–155 characters to the front matter of every post.
4. Create a 64 px and a 32 px logo for the header and favicon, and add `width`/`height` attributes.
5. Add `docs/404.html` and `docs/llms.txt`.

## Technical SEO (80)

**What works**
- HTTPS everywhere; `strict-transport-security` present (GitHub Pages).
- `robots.txt` allows all crawlers and declares the sitemap.
- `sitemap.xml` (jekyll-sitemap) lists all 8 indexable URLs with `lastmod` taken from `last_modified_at`. Google verification files are correctly excluded.
- Self-referencing canonicals on every page.
- Old `/ouestcharlie/...` URLs and the "OuEstCharly" typo URL redirect through `jekyll-redirect-from`.
- RSS feed at `/feed.xml`, advertised in `<head>`.

**Findings**

| Severity | Finding | Evidence | Fix |
|---|---|---|---|
| Medium | No custom 404 page | `/404.html` returns 404; GitHub Pages serves its generic page | Add `docs/404.html` with `permalink: /404.html`, a search hint, and links to the install guide and latest posts |
| Low | URLs are case-sensitive and mixed-case | `/2026/07/10/woof-is-different-…` returns 404 while `/Woof-is-different-…` returns 200. The same applies to `…Claude-Strava-OuEstCharlie-Woof/` | Don't rename (that loses accumulated signals). Use lowercase slugs for new posts. Optionally add lowercase `redirect_from` entries for the two mixed-case posts |
| Low | `cache-control: max-age=600` on all assets | Lighthouse: 616 KiB–2.3 MiB of "inefficient cache" | GitHub Pages can't change this. It matters less once images are smaller. A CDN in front (Cloudflare) would fix it if wanted |
| Info | Homepage `<url>` has no `lastmod` in the sitemap | sitemap.xml | Optional: add `last_modified_at` to `index.md` |
| Info | Unpublished post `2026-10-20-darktable-and-woof.md` uses the logo as `image:` and has no `description:` | front matter | Set a real screenshot and a description before publishing |

## Performance (55), mobile lab data from local Lighthouse

| Page | Perf | LCP | CLS | TBT | FCP |
|---|---|---|---|---|---|
| Home | 81 | **5.2 s** | 0.001 | 0 ms | 0.9 s |
| /2026/05/13/claude-how-to-step-by-step/ | 75 | **10.4 s** | 0 | 0 ms | 0.9 s |

The LCP element is a text paragraph. Its render is delayed by render-blocking CSS and by image downloads competing for bandwidth on the simulated slow connection:
- `woof_large_850.png` is **669 KB**, 850×850, and loads on *every* page for a 32 px header logo and the favicon. It loads twice on the homepage and the "Why" post.
- `ClaudeHowTo/016.png` is 936 KB, and several other screenshot PNGs are 100–170 KB.
- `<video>` elements have no `preload` attribute.

Field data (CrUX) isn't available: the site is below CrUX traffic thresholds, and the PageSpeed API quota was exhausted.

Fixes: a small logo (`woof_64.png` ≈ 5 KB, `favicon-32.png`, `apple-touch-icon.png` 180 px), converting screenshots to WebP or quantised PNG, `loading="lazy"` + `decoding="async"` on in-content images, and `preload="none"` on videos (they already have posters).

## Images (55)

- ✅ Every `<img>` has descriptive alt text.
- ❌ No `width`/`height` on any image (Lighthouse "unsized-images"). CLS is still ~0 because images sit inside centred paragraphs, but adding dimensions protects against regressions.
- ❌ `post-image.html` emits `max-height="600"`, which isn't a valid HTML attribute and has no effect. Use `style="max-height:600px;width:auto;max-width:100%"`.
- ❌ No `loading="lazy"`; long tutorials (13 screenshots) download every image up front.
- ⚠️ All PNG/JPG, no WebP/AVIF. Estimated savings: 663 KiB on the homepage and 2 MiB on the how-to.
- ⚠️ Videos of 9–26 MB are self-hosted on GitHub Pages. That's fine with `preload="none"`. Uploading to YouTube as well would add a discovery channel and video-SERP presence.

| Severity | Finding | Fix |
